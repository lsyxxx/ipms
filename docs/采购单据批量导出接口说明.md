# 采购单据批量导出

## 页面与行为

- 前端仓库：`E:/github/client_prod`。
- `/purchase/my`、`/purchase/all` 增加“导出单据”“导出任务”，原 Excel 导出保留。
- 后端根据点击时的关键字、状态、日期、部门和当前标签重新查询全部匹配记录，忽略 `page/limit`。
- 我的采购范围：`MY` 我创建的、`TODO` 待我处理、`DONE` 我已处理。身份由登录态获取，客户端不能指定其他用户。
- 全部采购范围：`ALL`，与现有全部采购列表使用相同的数据范围及搜索条件。搜索日期沿用现有列表查询语义。
- 开始生成之前将搜索结果编号写入快照；生成时按编号读取当前数据。查询快照扫描过程中不持有数据库长事务，单据内容不做版本快照。
- 已完成且已验收：采购单全部页在前，验收记录全部页在后，保留原页面方向。
- 未验收或流程未完成：正常导出采购单，不追加验收记录，不计入失败；清单注明具体原因。
- 每单一个 PDF：`单据编号-总金额-申请人-部门.pdf`。金额保留两位小数，非法文件名字符替换为下划线。
- ZIP 附 `导出结果清单.csv`（UTF-8 BOM，包含每单结果、无验收记录原因与失败原因）和 `导出说明.txt`。

## 接口

统一前缀 `/purchase/document-export`。JSON 使用项目已有 `R<T>`，所有接口均要求登录，任务查询、下载只允许创建者访问。

### POST /save

请求示例：

```json
{
  "scope": "ALL",
  "query": "试剂",
  "state": "已通过",
  "startDate": "2026-01-01",
  "endDate": "2026-12-31",
  "depts": "部门编号1,部门编号2"
}
```

`scope` 必填，可选 `MY/TODO/DONE/ALL`。其他字段为当前页面搜索条件；`depts` 仅对 ALL 有效。
返回 `R<PurchaseDocumentExportVO>`。同一用户同时只允许一个未完成任务。

### GET /findList

返回当前用户未过期的最近 50 个任务，包括两个页面创建的任务。

### GET /findById?id={任务编号}

返回单个任务。VO 字段：

| 字段 | 说明 |
| --- | --- |
| id、scope | 任务编号、查询范围 |
| status | 数字枚举：0 QUEUED 等待；1 QUERYING 查询；2 GENERATING 生成；3 PACKAGING 打包；4 COMPLETED 完成；5 FAILED 失败 |
| total、processed | 本次快照总数、已处理数 |
| success、failed | 成功 PDF 数、失败单据数 |
| withoutAcceptance | 成功 PDF 中未包含验收记录的数量，是 success 的子集 |
| message | 当前进度或最终统计 |
| fileName、fileSize | ZIP 下载名称、大小（字节） |
| createdAt、expiresAt | 毫秒时间戳；完成之前 expiresAt 为 0 |

任务窗口打开且存在未结束任务时每 3 秒刷新；关闭、离开页面后停止轮询，后台继续生成。刷新或重新进入页面可通过任务列表查看进度。

### GET /download?id={任务编号}

返回 `application/zip`，设置 UTF-8 文件名、Content-Length、no-store；服务端以文件流传输。

下载进度与后台生成进度分开显示。支持 File System Access API 的安全上下文浏览器直接写入所选文件，减少大 ZIP 的浏览器内存占用；其他浏览器接收 ZIP 后发起保存。后者仍需要浏览器缓存文件，超大导出建议使用支持该能力的 Chrome/Edge 并通过 HTTPS 访问。

## 运维与资源控制

- 不新增数据库表或迁移；所有查询通过 JPA，IN 批次最多 100 个主表编号，兼容 SQL Server 2014 参数数量限制。
- 专用线程池：2 个生成线程、10 个排队任务；队列满时明确拒绝，绝不转到请求线程同步生成。
- 编号、任务状态、清单及 ZIP 落盘，每批只加载 100 个主表及其完整明细，每单生成后立即清除中间文件。
- ZIP 使用流式写入；PDF 合并使用 PDFBox 的磁盘临时缓存，不增加 Aspose PDF 的合并水印或试用页数限制。现有 Excel 转 PDF 的授权仍沿用原部署配置。
- 默认目录：`${abt.temp.dir}/purchase-document-exports`；可通过 `abt.pur.export.dir` 配置专用目录。运行账号需要读写权限，目录必须位于非公开访问位置，并留足 ZIP 与临时文件空间。
- 结果从任务完成起保留 24 小时；每小时清理过期任务与文件，执行中任务不清理。
- 重启后可继续查看及下载已完成结果；中断任务标记失败并提示重新导出，不声称能断点续跑。
- 当前实现面向单实例。多实例部署需要固定路由到同一实例，或进一步引入共享任务存储、任务队列及共享文件存储。
- 单据生成失败会隔离并记入结果清单；磁盘、ZIP 写入等任务级故障会终止任务，不提供不完整 ZIP。
