# 报告封面信息维护

相关文档：[设计方案](报告封面信息维护设计方案.md)。

## 数据与约束

- 表：`dbo.report_cover_info`；执行 `sql/20261112_report_cover_info.sql` 建表，兼容 SQL Server 2014。
- 一条记录只有一个封面名称 `coverName`，去除首尾空白后全表唯一；大小写等比较规则遵循数据库排序规则。
- 一条记录可以关联多个 `T_checkModule.Id`，一个项目 ID 只能关联一条封面记录，禁用配置仍保留占用。
- Excel 一行中若包含多个独立封面名称，维护时拆为多条配置，共用的设备和标准分别填入。
- `checkModuleIds`、`instruments`、`standards` 在数据库中为 `NVARCHAR(MAX)` JSON 文本；Java、接口中直接使用字符串数组，未填写或传 `null` 均保存为 `[]`。
- 项目代码使用 `item_code` / `itemCode`，样品规格使用 `sample_spec` / `sampleSpec`，业务分类使用 `category`。
- 设备、标准保存完整文本，不关联其他设备、标准字典，保留顺序；列表项不能为空，保存时去除首尾空白。关联项目 ID 额外去重，保留首次出现顺序。
- 状态：`0` 禁用，`1` 启用，新增或全量更新时未传或传 `null` 默认启用。
- 继承 `com.abt.common.model.AuditInfo`，使用现有审计监听器。客户端不传审计字段，更新保留原创建信息。

## 接口

沿用系统认证及 `R<T>` 返回结构，统一前缀 `/report-cover-info`。返回数据为 VO，不直接返回实体。

| 方法 | 路径 | 参数 | 返回 data |
| --- | --- | --- | --- |
| GET | `/findById` | `id`，必填 | 封面详情 |
| GET | `/findPage` | 查询参数 | `Page<ReportCoverInfoVO>` |
| GET | `/findList` | 查询参数 | `List<ReportCoverInfoVO>` |
| POST | `/save` | JSON 请求体，不允许传 id | 新增后的详情 |
| POST | `/update` | JSON 请求体，id 必填 | 更新后的详情 |
| DELETE | `/delete` | `id`，必填 | 无，提示删除成功 |

删除为物理删除，释放项目关联占用。记录不存在时，详情、更新、删除均返回业务异常。

### 操作权限

编辑、删除使用现有 `@Secured` 方法权限机制，分别校验当前用户的角色 ID：

| 接口 | 权限 ID | 角色名称 |
| --- | --- | --- |
| `POST /report-cover-info/update` | `JS_REPORT_COVER_EDIT` | 报告封面信息编辑 |
| `DELETE /report-cover-info/delete` | `JS_REPORT_COVER_DEL` | 报告封面信息删除 |

执行 `sql/20261112_report_cover_info_roles.sql` 初始化角色，再通过现有用户角色授权界面分配。脚本可重复执行，不自动授予用户权限。用户重新登录后权限生效；编辑权限与删除权限相互独立。查询、新增沿用系统认证。

### 新增及更新

```json
{
  "coverName": "岩石主量元素分析",
  "checkModuleIds": ["旧系统检测项目ID1", "旧系统检测项目ID2"],
  "itemCode": "QYZL",
  "sampleSpec": "200目 0.7g",
  "sampleStatus": "粉末",
  "instruments": ["日本理学 ZSXPimusⅢ+ X射线荧光光谱仪", "PR124ZH 电子天平"],
  "standards": ["硅酸盐岩石化学分析方法 第28部分 GB/T 14506.28-2010"],
  "category": "化学",
  "version": "2026",
  "ownership": "ABT",
  "remark": "",
  "status": 1
}
```

更新在相同结构中补充 `id`，为全量更新：未传的可选文本清空，未传的列表清空，状态按上述默认规则处理。

名称必填，最长 256 字符；项目 ID 最长 50 字符；项目代码、分类最长 64 字符；规格最长 500 字符；样品状态最长 200 字符；版本最长 32 字符；归属最长 128 字符；备注最长 1000 字符。项目代码允许为空和重复，关联项目可以暂不填写。实际项目 ID 必须在 `T_checkModule` 中存在。

### 查询参数

| 参数 | 说明 |
| --- | --- |
| `coverName` | 封面名称模糊匹配 |
| `itemCode` | 项目代码模糊匹配 |
| `category` | 分类精确匹配 |
| `version` | 版本精确匹配 |
| `ownership` | 归属精确匹配 |
| `status` | 可选，0 或 1；不传查询全部状态 |
| `page` | 页码，从 1 开始，默认 1 |
| `limit` | 每页数量，默认 20；传 0 也使用 20，上限 999 |

列表接口不分页，忽略分页参数；默认排序为 `createDate DESC, id DESC`。本期不支持按关联项目名称筛选封面。

详情、分页、列表及保存结果均包含原业务字段和以下附加字段：

```json
{
  "checkModules": [
    {"id": "旧系统检测项目ID1", "name": "检测项目最新名称1"},
    {"id": "旧系统检测项目ID2", "name": "检测项目最新名称2"}
  ],
  "createDate": "2026-11-12 16:00:00",
  "createUserid": "创建人ID",
  "createUsername": "创建人姓名",
  "updateDate": "2026-11-12 16:00:00",
  "updateUserid": "更新人ID",
  "updateUsername": "更新人姓名"
}
```

先查询封面，再按当前结果中的项目 ID 去重批量查询 `T_checkModule.Id/Fname`，每批最多 1000 个参数。返回顺序与 `checkModuleIds` 一致。旧系统外部删除了项目时仍保留 ID，`name` 返回 `null`；不会静默删除关联。

## 一致性与部署

- 新增、更新、物理删除在 service 事务中统一申请 SQL Server `sys.sp_getapplock` 独占锁，资源名为 `ipms.report_cover_info.write`，超时 10 秒。锁由数据库在事务结束时释放，支持多个应用实例。
- 加锁后进行名称校验、项目存在性检查及项目唯一归属检查；失败时回滚。名称唯一性另有数据库唯一约束。
- JSON 字段无法使用普通外键、唯一索引约束其中的项目 ID，因此必须通过维护接口写入，不能绕过接口直接修改关联 JSON。归属检查目前扫描已有配置并在程序内比较 ID，适用于基础配置数据规模。
- 数据库账号需能够调用 `sys.sp_getapplock`。JPA 和 JdbcTemplate 使用应用的同一数据源及事务，部署时需要在实际 SQL Server 上验证锁超时、提交释放和并发冲突。
- 建表脚本不修改现有项目数据，不导入 Excel，不添加前端页面或报告生成功能。
