# 野外用车后端接口说明

实现位置：IPMS `com.abt.oa`，接口前缀 `/field-vehicle`。旧前端使用 `requestJava()`，代理前缀 `/japi` 由环境配置，不属于 Controller URL。本次不包含前端页面。

## 部署

1. 在目标业务库执行 [建表脚本](../sql/20261105_field_vehicle.sql)。只新增主表 `oa_field_vehicle_use`、加油表 `oa_field_vehicle_fuel`；不要只依赖 Hibernate ddl-auto，过滤唯一索引和条件 CHECK 必须由脚本创建。
2. 已有 V1.3 环境需在切换新版服务前暂停加油写入，执行 [实时汇总升级脚本](../sql/20261105_field_vehicle_realtime_totals.sql)。复用已有三列，回填草稿／使用中记录，设置非空零值默认及新版约束，保留已结束记录结算值、明细、审计和车辆状态；失败整笔回滚，可重复执行。新环境也可重复执行此脚本。
3. 如果两表由 Hibernate 自动创建且字段与设计一致，再执行 [约束补齐脚本](../sql/20261105_field_vehicle_constraints.sql)，补齐八项检查约束及加油主表外键。发现非法数据整笔回滚，不改删业务记录；可重复执行。
4. 执行 [负责人角色初始化](../sql/20261105_field_vehicle_manager_role.sql)，通过现有授权管理把 `JS_OA_FIELD_VEHICLE_MANAGER` 分配给负责人，再刷新登录。脚本不自动授权普通用户。
5. 加载新版后端。现有同名表结构不一致时，初建脚本不会自动修复，应先进行独立的数据迁移评审。此功能没有审批流程，也不会修改旧用车业务代码。

## 权限及状态

所有登录用户可查全部记录（含草稿）。第一期只有负责人可写，可交接管理其他负责人创建的记录，但物理删除仅限本人创建的草稿；手填司机、同行人不自动获得写权限。

状态：`0` 草稿、`1` 使用中、`2` 已结束。草稿不占车、不记加油；正式提交把对应 `CarInfo.IsUse` 持久化为 `1`，还车写为 `0`，均与主表操作同一事务。已结束记录和费用不可改删、不可重开。

两张实体继承 `com.abt.common.AuditInfo`，返回创建／修改人及时间；初次草稿创建时间保留，派车时间按此 createDate 展示。主键为 UUID 字符串：现有 TimestampIdGenerator 仅拼毫秒时间，故本模块使用 UUID 避免并发创建主键碰撞，不改旧模块生成器。

## 接口

所有响应沿用现有 `R<T>`，返回 VO，分页为 Spring Data `Page<VO>`。

| 方法 | 路径 | 输入 | 用途 |
|---|---|---|---|
| GET | `/findPage` | page、limit、carId、status、driverName、peerName、startDate、endDate、query | 分页，日期筛选实际用车日期 |
| GET | `/findById` | id | 完整详情及还车表单实时合计 |
| GET | `/car/findList` | query（车牌）、isAvtive（0停用、1启用，默认1） | 车辆使用状态、自动起始里程与首次填写提示 |
| POST | `/draft/save` | 保存表单，可空 `{}`；更新草稿带 id | 保存草稿，不校验正式必填、不占车 |
| POST | `/delete` | id（JSON 请求体） | 仅物理删除本人创建的草稿 |
| POST | `/save` | 完整保存表单，可带草稿 id | 正式派车或草稿原地提交 |
| POST | `/update` | id、drivers、peers、purpose、departurePlace、destination | 使用中五项资料完整替换 |
| POST | `/fuel/save` | mainId、fuelDate、amount、fuelQuantity、remark | 新增加油 |
| POST | `/fuel/update` | id 加上述加油字段 | 修改加油，不能换绑主表 |
| POST | `/fuel/delete` | id、mainId | 删除使用中加油记录 |
| POST | `/return/update` | id、endDate、endMileage | 后端重新汇总、结束记录、释放车辆 |

分页 page 从 1 开始，limit 默认 20，最大 100；默认 useDate、createDate、id 降序。driverName、peerName 均为姓名包含查询，例如“张三”可匹配“张三丰”；两个条件同时填写时按 AND 组合，直接在司机／同行人完整文本中匹配，空白条件不筛选。查询中的 `%`、`_`、`[`、`!` 按普通文字转义，不作为通配符。query 按车牌快照／用途／两地模糊匹配，日期范围包含两端。分页不展开一对多费用，所有状态的三项加油合计直接读取主表，查询不再临时聚合或回写。

车辆查询示例：`GET /field-vehicle/car/findList?isAvtive=1&query=陕A`。`isAvtive` 沿用车辆档案既有字段拼写，不传默认查询启用车辆，传 `0` 查询停用车辆。列表同时返回空闲和使用中的车辆，新增字符串字段 `isUse`：`0` 空闲、`1` 使用中；车辆档案 `IsUse=1` 或存在使用中的野外用车记录时均返回 `1`。原有 `carId`、`carNo`、`startMileage`、`requiresInitialMileage` 保留。前端根据使用状态禁选占用车辆，正式派车仍由后端检查启用及占用状态；本次无需数据库结构变更。

## 派车与草稿

人员格式示例：`"drivers":"张三、李四", "peers":"王五"`。已有环境先执行 `scripts/migrate_field_vehicle_names.ps1`，将旧 JSON 转为文本并重命名为 drivers／peers；该脚本仅作用本地 ZJData，其他环境需按相同规则单独迁移。

正式表单示例，首次填写起始公里数：

```json
{
  "carId": "CAR001",
  "drivers": "张三",
  "peers": "",
  "purpose": "野外采样",
  "departurePlace": "公司",
  "destination": "现场",
  "useDate": "2026-11-05",
  "expectedReturnDate": null,
  "startMileage": 15000.0,
  "remark": "携带采样设备"
}
```

草稿允许省略必填内容，使用 `Default+Temp` 校验组；正式提交使用 `Default+Apply` 完整校验。已填字段的长度、非负数、精度及日期先后关系仍受限制。数据库草稿业务列可空，不受 entity 默认组必填约束阻挡。

司机、同行人改为纯字符串，前端输入原样保存返回，不拆分、trim 或 JSON 转换；正式司机使用 @NotBlank 校验，同行人可空。预计返回日期可空，填值时不得早于 useDate。草稿可改全部表单，正式派车后仅五项资料可改，不改车辆、日期、里程和备注。

后续派车 startMileage 自动取该车最近一次野外还车的 endMileage，按实际 returnTime 顺序取值；不读写旧 InitialKil／SyInitialKil。客户端后续可不传起始值，若传旧值与自动值不一致会提示刷新。

删除草稿：POST `/field-vehicle/delete`，请求体：

```json
{
  "id": "FV001"
}
```

负责人在事务内锁定主记录，重新校验 status=0 且 createUserid 等于当前登录用户 ID 后，通过 JPA 物理删除，成功响应 data 为空、msg 为“删除成功”。不能删除他人草稿、使用中或已结束记录；已删除／不存在记录返回业务错误。若异常存在加油明细则拒绝并提示核实数据，不级联删除费用。删除不改车辆状态、里程或其他记录，并记录操作日志；与草稿正式提交竞争同一主记录锁，防止提交后被误删。无需数据库结构变更，沿用负责人权限，abt112 无需额外授权。

## 加油与还车

```json
{
  "mainId": "FV001",
  "fuelDate": null,
  "amount": 300.0,
  "fuelQuantity": 40.5,
  "remark": "现场加油"
}
```

amount 必填、>0、最多两位小数；fuelQuantity 为升，必填、>0、最多三位小数。fuelDate、remark 可空，说明最多 1000 字符，修改时缺省／null／空白可清空说明。Java／接口关联字段为 mainId，数据库列 m_id。日期为空不按创建日期补齐，也不影响金额、升数和次数累计。

主表三项统计从创建时就保存为零。每次加油新增、修改、删除都先锁主记录，在同一事务中落明细，再按全部现存明细重新 SUM(fuelQuantity)、SUM(amount)、COUNT(id)，覆盖主表 `fuelTotalQuantity`（升）、`fuelTotal`（元）、`fuelCount`（条数）。删除最后一条后保存 `0.000`、`0.00`、`0`；按明细重算，不按原值简单加减。汇总更新失败时，明细变更一并回滚。

打开还车表单先 GET `/findById`，只读展示主表已实时维护的三项统计，前端不需要自行计算或提交合计。加油维护成功后刷新详情获取新值。数据加载失败不能显示为零值并继续提交。

```json
{
  "id": "FV001",
  "endDate": "2026-11-07",
  "endMileage": 15320.5
}
```

还车提交后在车辆锁、主记录锁内重查状态，再按全部有效加油记录核算并覆盖主表三项统计，随结束状态冻结；无加油写 `0.000`、`0.00`、`0`，同日多笔逐条计次，空日期也计入。结束日期须 ≥ 用车日期及最大非空加油日期，结束里程须 ≥ 起始里程。

汇总落库、结束记录、车辆释放同一事务提交；任何一步失败全部回滚。预览到提交之间加油发生变化时，以还车事务内最终计算值为准，响应返回冻结后的详情，前端据此刷新。已结束不能再维护费用或改写统计，所有状态的列表与详情统一读取主表持久化值。

## 测试

定向运行，项目默认 skipTests=true，必须覆盖该值：

```powershell
& 'D:\apache-maven-3.9.3\bin\mvn.cmd' -o -q -pl admin -am '-Dtest=FieldVehicle*Test' '-Dsurefire.failIfNoSpecifiedTests=false' '-DskipTests=false' test
```

真实 SQL Server 测试额外设置 `IPMS_TEST_SQL_USER`、`IPMS_TEST_SQL_PASSWORD` 环境变量，并传 `'-Dfield.vehicle.sqlserver.test=true'`。测试仅创建随机前缀 `ipms_field_vehicle_test_` 的独立库，结束删除此测试库，不写现有业务库；使用 SQL Server 2014 方言及数据库兼容级别 120。Windows 环境如 Mockito 动态附加受限，可在 JVM 启动时通过 argLine 加载本地 byte-buddy-agent。

覆盖空草稿、仅创建人草稿物理删除、并发提交防误删、分组校验、权限、手填姓名模糊筛选及特殊字符、可选日期／说明、必填升数、主从归属、实时预览与提交重算、无加油零值、结束冻结、同车并发派车、费用与还车竞争、数据库异常回滚。宿主测试数据库为 SQL Server 2022，不能据此声称已在 2014 实机验证。

## 兼容边界

旧业务共享 IsUse，但旧 C# 未参与本模块全部锁协议，仍需遵守车辆占用状态，不能宣称实现了跨新旧业务的严格双向互斥。野外里程独立于旧业务，期间穿插其他用车时表显差值可能包含其他行驶，本版不自动纠正。
